# Celan Learning App Build Manual

## Purpose

Build a first-release Celan learning app with two complete ways to study:

1. **Build Words** — learn through roots, compounds, meanings, spelling, and pronunciation.
2. **Fix Sentences** — learn through VSO order, grammar markers, transformations, and sentence repair.

The mission of both paths is the same: **learn Celan**. They use the same curriculum and share progress. The learner may switch paths at any time without restarting.

This first release does **not** require AI. The Celan database remains the authority, and the app creates controlled exercises from approved words, rules, and examples.

---

## 1. What already exists

The project already contains most of the language material needed for the first release:

- The browser app in `dictionary/`
- The assembled dictionary in `data/dictionary_entries.csv`
- Approved expansion vocabulary in `data/lexicon_expansions.csv`
- Root data in `data/roots_and_morphology.csv` and `data/expanded_root_database.csv`
- Working grammar lessons in `data/grammar_rules_working.csv`
- More than 2,000 sentences in `data/phrases_and_examples.csv`
- Social expressions in `data/expressions.csv`
- The beginning of a course in `learning_center/week_01.md`
- Offline embedded data generated by `dictionary/build_embedded_data.js`
- Existing browser behavior and tests in `dictionary/script.js` and `dictionary/search.test.cjs`

The current app uses plain HTML, CSS, and JavaScript. Keep that structure for the first learning release. A framework rewrite is not needed.

## 2. First-release scope

### Include

- A Learning Center inside the existing app
- A choice between Build Words and Fix Sentences
- One shared beginner curriculum
- Five difficulty stages
- Deterministic answer checking
- Hints and explanations
- Local progress saving
- Spaced review
- Keyboard, mouse, and touch support
- Optional pronunciation playback when audio exists
- A developer-friendly way to add lessons without rewriting JavaScript

### Do not include yet

- Open-ended AI conversations
- AI-generated Celan
- Speech recognition or pronunciation scoring
- Accounts or cloud synchronization
- Branching story campaigns
- Multiplayer features
- A full eight-nation dialogue simulator
- Automatic acceptance of invented compounds

Those can be added after the two core paths are reliable.

## 3. The learner experience

Add a new top-level tab to the existing app:

```text
Dictionary | Expressions | Grammar Guide | Phrase Builder | Learning Center
```

The Learning Center opens with one primary action and two study choices:

```text
CONTINUE LEARNING

CHOOSE A STUDY PATH

BUILD WORDS
Learn through roots and compounds.

FIX SENTENCES
Learn through structure and repair.
```

The learner should always be able to:

- Continue the next recommended lesson
- Choose either study path
- Review material that is due
- See current skill levels
- Revisit a completed lesson
- Open the relevant dictionary or grammar entry

The path choice changes the kind of activity, not the underlying course position.

---

## 4. Shared curriculum

Both paths teach the same learning objectives. A learning objective is one concrete ability, such as:

- Recognize the root `Dren`
- Explain the basic meaning of `Krez`
- Identify a verb in a simple sentence
- Put a three-part sentence into VSO order
- Form a command with `Va`
- Form a question with `Ra`
- Negate a verb with `Ver`
- Use a past or future prefix
- Recognize a compound built from two familiar roots

Each objective receives at least one Build Words activity and one Fix Sentences activity whenever both paths make sense.

Example:

```text
Objective: Understand and use Var.

Build Words version:
- Match Var to its core motion meaning.
- Recognize Var in related forms.
- Distinguish Var from other movement words.

Fix Sentences version:
- Arrange var / I / dren.
- Add Ra to make a question.
- Add Ver to make the sentence negative.
- Add Nor- to place the action in the future.
```

The first curriculum can grow from `learning_center/week_01.md`. Preserve its plain teaching sequence: hear the action-first structure, recognize it, build it, and use it.

## 5. Difficulty stages

Use the same five stages across both paths.

### Stage 1: Recognize

The learner identifies a known item with strong support.

- Choose a root meaning from three options
- Tap the verb in a sentence
- Hear or read a model before answering
- Use translations and color cues

### Stage 2: Assemble

The learner builds an answer from supplied pieces.

- Join two supplied root cards
- Arrange words into VSO order
- Add a supplied marker such as `Ra`, `Va`, or `Ver`
- Use a visible grammar reminder

### Stage 3: Produce

The learner supplies the answer with less help.

- Type a known headword from its meaning
- Identify the roots without highlighted boundaries
- Complete a sentence with a missing word
- Transform a sentence without draggable pieces

### Stage 4: Adapt

The learner changes language for a new purpose.

- Infer a familiar compound in a new context
- Change a statement into a question or command
- Change tense, subject, number, or polarity
- Select between several grammatical but contextually different answers

### Stage 5: Operate

The learner works with little assistance.

- Explain an unfamiliar approved compound from known parts
- Repair several problems in one sentence
- Produce a complete sentence from an English intention or scene
- Read a short connected passage and answer in Celan

Do not introduce a timer until the learner has already demonstrated accurate understanding. Timed play is an optional challenge, not the definition of mastery.

## 6. Mastery and advancement

Do not advance learners merely because they finished a screen. Advance them when they can demonstrate the skill again.

Track mastery separately for each objective:

```text
0 — New
1 — Introduced
2 — Practiced
3 — Secure
4 — Mastered
```

Recommended starting rules:

- **Introduced:** one correct supported answer
- **Practiced:** two correct answers using different exercise forms
- **Secure:** three correct answers across at least two sessions, including one answer without hints
- **Mastered:** a correct later review after at least seven days, including one production task

A unit is complete when:

- Every required objective is at least Secure
- The learner scores at least 80% on the unit check
- The learner completes at least one production exercise

These values are starting settings, not permanent truths. Store them in configuration so they can be tuned after real learner testing.

### Separate skill levels

Do not reduce the learner to one language level. Track at least:

- Roots and compounds
- Vocabulary recall
- Sentence order
- Grammar markers
- Reading
- Written production

A learner may be strong at recognizing roots but still need work on sentence production.

## 7. Build Words path

### Goal

Teach learners to see Celan words as meaningful structures rather than isolated spellings.

### Exercise types

#### A. Root recognition

Show one root and ask for its approved core meaning.

```text
Krez

[ Fire / heat ]
[ Water / flow ]
[ Stone / endurance ]
```

#### B. Find the shared root

Show several approved headwords and ask which root they share.

#### C. Break the compound

Show an approved compound and ask the learner to select its recorded parts.

Only use recorded derivations. Do not guess how a word divides from spelling alone.

#### D. Meaning from parts

Show an approved word, its recorded roots, and several meaning choices. Wrong choices should be plausible but clearly contradicted by the recorded meaning.

#### E. Build the approved word

Give a recorded meaning and a small set of root or affix cards. The learner constructs the approved headword.

#### F. Word family sorting

Ask the learner to sort approved words by root family, meaning family, or grammatical type.

#### G. Context choice

Show a canonical example sentence with one missing word and ask the learner to choose the correct member of a known family.

### Rules for safe generation

- Use only app-facing approved headwords.
- Use recorded derivations from approved data.
- Treat euphonic forms as variants, not separate vocabulary.
- Never tell learners that every possible root combination is a dictionary word.
- Label a construction exercise as creative only when the app is not claiming the result is canonical.
- Do not expose hidden technical root descriptions as extra dictionary meanings.
- Preserve all approved senses of polysemous words.

### Difficulty controls

Increase difficulty by changing one or more of these:

- Familiar root to unfamiliar root
- One root to multiple roots
- Visible segmentation to hidden segmentation
- Multiple choice to typing
- Direct meaning to contextual meaning
- Literal compound to an approved lexicalized meaning
- Immediate review to delayed recall

## 8. Fix Sentences path

### Goal

Make Celan sentence movement feel natural, especially action-first VSO structure.

### Exercise types

#### A. Identify the slots

Mark the verb, subject, object, destination, or grammatical signpost.

#### B. Reorder the sentence

Scramble a canonical example and ask the learner to restore it.

#### C. Add the signpost

Ask the learner to add `Ra`, `Va`, `Ver`, `Rath`, or another taught marker.

#### D. Transform the sentence

Start with one approved sentence and request one controlled change:

- Statement to question
- Statement to command
- Positive to negative
- Present to past or future
- Singular to plural
- One pronoun to another

#### E. Fill the gap

Remove one word or grammatical marker from a canonical sentence.

#### F. Diagnose the error

Show one sentence with one known error. Ask what is wrong before asking for the repair.

#### G. Repair several errors

At later stages, combine word order, tense, agreement, and context errors.

#### H. Produce the sentence

Give a controlled meaning or scene and ask the learner to type the whole answer.

### Rules for safe generation

- Begin from a canonical or explicitly approved teaching sentence.
- Apply only documented grammar transformations.
- Store every allowed transformed answer or generate it with a tested rule.
- Never assume English word order when creating a prompt.
- Keep punctuation and semantic capitalization rules separate from ordinary answer normalization.
- Do not mark an alternate answer wrong merely because it differs in optional euphony.
- If two forms change meaning, do not normalize them into the same answer.
- When a source rule is still marked ambiguous, use the current app-facing teaching rule and flag the exercise for editorial review.

### Answer normalization

Safe normalization may ignore:

- Leading or trailing spaces
- Repeated internal spaces
- Terminal punctuation in early exercises
- Case where capitalization is not being tested
- An explicitly recorded euphonic variant

Do not ignore:

- Word order
- Missing grammatical markers
- A tense or aspect marker being tested
- Meaningful capitalization in capitalization lessons
- Apostrophes or hyphens when they carry grammatical meaning
- A different pronoun or clusivity choice

## 9. Feedback after an answer

Every answer should produce useful feedback.

### Correct answer

Show:

- The complete Celan form
- A short explanation of why it works
- The relevant root or rule
- A pronunciation button when audio is available

### Incorrect answer

Show:

- Which part needs attention
- One plain-English explanation
- A small hint before revealing the answer
- The corrected form after the learner tries again

Avoid generic messages such as “Wrong” or “Try again” without explanation.

Example:

```text
Not quite.

Celan puts the action first. Move var before I.

Correct form: var I dren.
```

Do not punish an error by immediately lowering a visible score. Record the error for review and let the learner repair it.

---

## 10. Review scheduling

The first version can use a simple review schedule:

```text
Incorrect answer: review again during the same session
First correct answer: review tomorrow
Second correct answer: review in 3 days
Secure objective: review in 7 days
Mastered objective: review in 21 days
```

If the learner gets an item wrong during delayed review, shorten the interval and provide a related easier exercise before repeating the same form.

Review should mix paths when useful. A word learned in Build Words can later appear inside a Fix Sentences review.

## 11. Data design

Keep canon data separate from teaching data.

The dictionary and grammar remain the language authority. The Learning Center adds references, sequencing, prompts, distractors, and teaching notes without rewriting canonical definitions.

### Recommended new files

#### `learning_center/curriculum.csv`

One row per learning objective.

Suggested fields:

```text

unit_id

prerequisite_ids
related_headword_ids
```

### Generated data

Do not edit `dictionary/embedded_data.js` by hand.

## 12. Progress storage

Use browser `localStorage` for the first release.

Store a single versioned progress object:

```json
{
  "schemaVersion": 1,
  "activeUnitId": "UNIT-01",
  "preferredPath": "words",
  "objectives": {
    "OBJ-001": {
      "mastery": 2,
      "attempts": 4,
      "correct": 3,
      "hintedCorrect": 1,
      "lastSeen": "2026-09-17T14:30:00Z",
      "dueAt": "2026-09-20T14:30:00Z"
    }
  }
}
```

Requirements:

- Version the schema from the beginning.
- Provide a visible Reset Progress control with confirmation.
- Add Export Progress and Import Progress as JSON before adding accounts.
- Never store canon content inside the progress object.
- If lesson data changes, retain progress by stable objective IDs.

## 13. Suggested code structure

Keep the current app and add focused modules rather than enlarging `dictionary/script.js` indefinitely.

Recommended files:

```text
dictionary/
├── index.html
├── styles.css
├── script.js
├── embedded_data.js              generated
└── learning/
    ├── learning-center.js         navigation and lesson sessions
    ├── curriculum.js              curriculum loading and prerequisites
    ├── word-exercises.js          Build Words rendering and checking
    ├── sentence-exercises.js      Fix Sentences rendering and checking
    ├── mastery.js                 scoring and review scheduling
    ├── progress-store.js          localStorage import/export/versioning
    └── answer-normalization.js    controlled answer comparison
```

Keep parsing and canon assembly centralized. Learning modules should consume the same assembled entries used by the dictionary rather than creating a second dictionary implementation.

## 14. Build sequence

### Phase 0: Protect the language data

Before building exercises:

1. Keep source-facing and app-facing layers separate.
2. Use `data/dictionary_entries.csv` for convenient app display, but trace teaching items back to stable source IDs.
3. Treat `data/grammar_rules_working.csv` as the learner-facing grammar sequence.
4. Do not alter canon merely to simplify an exercise.
5. Add a validation rule requiring every exercise to cite its source word, rule, or example.

**Done when:** every planned exercise can point to approved project data.

### Phase 1: Learning Center shell

1. Add the Learning Center navigation button.
2. Add the Learning Center view to `dictionary/index.html`.
3. Build the path selector.
4. Build Continue, Review, and Progress cards.
5. Add responsive styles.
6. Load empty curriculum and progress objects safely.

**Done when:** the user can enter the Learning Center, choose a path, and leave without affecting the existing app.

### Phase 2: Shared curriculum and progress

1. Create the first curriculum CSV.
2. Convert Week 1 into stable objectives.
3. Load prerequisites and determine the next available lesson.
4. Add local progress storage.
5. Add objective mastery and due-review calculations.
6. Add reset, export, and import controls.

**Done when:** completing a placeholder exercise updates progress and survives a page reload.

### Phase 3: Build Words

Implement in this order:

1. Root-to-meaning matching
2. Shared-root recognition
3. Compound segmentation
4. Meaning-from-parts selection
5. Approved-word construction
6. Context selection

Start with manually curated exercises. Add safe automatic exercise generation only after the manual version is tested.

**Done when:** a learner can complete the first unit entirely through Build Words and receive clear feedback and review items.

### Phase 4: Fix Sentences

Implement in this order:

1. Slot identification
2. VSO reordering
3. Questions with `Ra`
4. Commands with `Va`
5. Negation with `Ver`
6. Past and future transformations
7. Fill-the-gap exercises
8. Typed production

Use `phrase_builder/evaluation/evaluation_set.csv` as a useful test source, not as the entire curriculum.

**Done when:** the same first unit can be completed entirely through Fix Sentences.

### Phase 5: Shared review

1. Mix due objectives from both paths.
2. Move from recognition exercises toward production during later reviews.
3. Add a short unit check.
4. Show skill-specific progress.
5. Recommend—but do not require—the weaker path.

**Done when:** progress earned in one path affects the same objective in the other path.

### Phase 6: Polish and release

1. Test keyboard and screen-reader behavior.
2. Test on phone, tablet, and desktop widths.
3. Add empty, error, and no-progress states.
4. Add content validation scripts.
5. Add automated tests.
6. Rebuild embedded data.
7. Verify that the app still opens directly from `dictionary/index.html`.

**Done when:** the app works offline, preserves progress, and does not break the existing Dictionary, Expressions, Grammar Guide, or Phrase Builder.

## 15. First unit specification

Use the existing Week 1 theme: **The First Motion**.

### Required objectives

1. Recognize that Celan normally places the action first.
2. Identify verb, subject, and object or destination.
3. Recognize and use `Var`.
4. Arrange a simple VSO sentence.
5. Recognize and use the imperative marker `Va`.
6. Produce five basic commands.

### Build Words activities

- Match `Var` to motion or going.
- Distinguish `Var` from several familiar non-motion roots.
- Find `Var` in approved related forms when the relationship is recorded.
- Match key Week 1 words to their meanings.
- Complete a canonical sentence with the correct word.

### Fix Sentences activities

- Identify the action in `var I dren.`
- Arrange `var / I / dren`.
- Add `Va` to form a command.
- Distinguish a statement from a command.
- Produce five approved command patterns.

### Unit check

The learner must:

- Correctly identify the action-first pattern
- Arrange three simple sentences
- Form three commands
- Type at least one complete answer without tokens
- Reach 80% overall

## 16. Content authoring workflow

Every learning item should follow this process:

1. Choose one learning objective.
2. Find the relevant approved headword, rule, and example IDs.
3. Decide which path and stage the item belongs to.
4. Write one plain prompt.
5. Record the correct answer and accepted variants.
6. Write one useful hint.
7. Write one short explanation.
8. Validate all cited IDs.
9. Test the item in the browser.
10. Mark the item approved for teaching.

Avoid exercises that accidentally test several untaught rules at once.

### Distractor rules

A wrong option should reveal a useful misunderstanding. Good distractors include:

- A root from the same broad meaning area
- English-style SVO order
- A question marker placed in the wrong position
- A tense marker applied to the wrong element
- A related word with the wrong grammatical type

Do not use nonsense spellings merely to make the right answer obvious.

## 17. Validation and testing

### Content validation

Create a script such as:

```text
learning_center/validate_learning_content.js
```

It should fail when:

- An objective ID is duplicated
- An exercise ID is duplicated
- A referenced objective does not exist
- A referenced headword, rule, or example ID does not exist
- A required correct answer is blank
- An accepted answer duplicates a wrong answer
- An exercise is marked approved without source IDs
- A prerequisite creates a cycle
- A Build Words exercise treats a variant as a new headword

### Automated behavior tests

Test at least:

- Loading the curriculum
- Unlocking prerequisites
- Saving and restoring progress
- Review scheduling
- Path switching
- Answer normalization
- Euphonic variant acceptance
- VSO word-order checking
- Hint penalties or hint tracking
- Unit completion
- Progress export and import

### Human language review

Before releasing a unit, manually check:

- Every Celan answer against the app-facing dictionary and grammar
- Whether the prompt has more than one defensible answer
- Whether the stated explanation is actually supported
- Whether optional euphony is handled correctly
- Whether capitalization and punctuation are intentionally tested
- Whether the exercise teaches Celan rather than English translation habits

---

## 18. Accessibility and usability

- Do not rely on color alone to show verb, subject, and object.
- Give draggable tokens keyboard alternatives such as Move Left and Move Right.
- Use real buttons with visible focus states.
- Announce correct and incorrect feedback through an `aria-live` region.
- Allow reduced motion.
- Make timers optional.
- Keep instructions short and reveal deeper explanations on request.
- Ensure all primary activities work without audio.
- Provide written pronunciation support when audio is unavailable.

## 19. Release checklist

The first release is ready when:

- [ ] The existing four app surfaces still work.
- [ ] Learning Center opens from the main navigation.
- [ ] Build Words can teach and assess Unit 1.
- [ ] Fix Sentences can teach and assess Unit 1.
- [ ] Both paths update the same objective progress.
- [ ] Progress survives a reload.
- [ ] Progress can be exported, imported, and reset.
- [ ] Incorrect answers receive a useful explanation.
- [ ] Review items return on schedule.
- [ ] Every approved exercise cites valid canon data.
- [ ] Optional variants are handled correctly.
- [ ] Content and behavior tests pass.
- [ ] Embedded data is rebuilt.
- [ ] The app works when opened locally without a server.
- [ ] The layout works on a phone.

---

## 20. What comes after the first release

Once the two core paths are stable, add features in this order:

1. More curriculum units
2. Recorded pronunciation and listening exercises
3. A conversation path using authored dialogue
4. Regional register practice
5. Story missions that reuse existing objectives
6. Optional AI feedback for genuinely open answers

AI should remain bounded by the approved Celan data. It may explain or practice the language, but it should not silently become the source of Celan canon.

---

## Final product rule

The learner should feel that they have two different ways to reach the same destination:

```text
BUILD WORDS
Understand how Celan grows.

FIX SENTENCES
Understand how Celan moves.
```

The first release succeeds when either path can carry a beginner through the same foundational Celan course, while switching between them feels seamless.
